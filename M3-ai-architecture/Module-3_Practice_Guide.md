**ПРАКТИЧЕСКОЕ ЗАНЯТИЕ (ПР5). Roofline-анализ: определение compute-bound и memory-bound операций**

**Цели занятия:**

* Научиться строить Roofline-диаграмму для заданной конфигурации «модель + аппаратная платформа».

* Освоить расчёт Arithmetic Intensity (AI) ключевых операторов нейросети.

* Научиться определять точку перегиба (ridge point) и классифицировать операторы как compute-bound или memory-bound.

* Научиться прогнозировать, какой ресурс (FLOPS или память) будет лимитировать производительность до запуска кода.

**Формируемые компетенции:**

* HPC-1.1 – обеспечивает выбор наилучшей вычислительной архитектуры под задачу ИИ.

* HPC-1.2 – разрабатывает эффективные вычислительные реализации параллельных алгоритмов ИИ на современных архитектурах.

**Материалы и инструменты:**

* Python 3.8+ с библиотеками NumPy, Matplotlib (для расчётов и построения графиков) или Excel.

* Паспортные данные целевой платформы (NVIDIA A100, H100, Jetson Orin — Peak FLOP/s, Peak Bandwidth).

* Список операторов нейросети (FC, Conv2D, Attention, ReLU и др.) с параметрами, выдаваемый преподавателем.

**Ход занятия:**

1. Вводная часть (10 мин) — постановка целей, повторение теории Roofline Model, разбор формулы Ridge Point (AI_ridge = Peak FLOP/s / Peak Bandwidth).

2. Этап 1. Характеристика целевой платформы (10 мин):

* определение Peak FLOP/s (FP16/BF16) и Peak Bandwidth (HBM) для заданной платформы;

* расчёт Ridge Point (пример для A100: 312/2000 = 156 FLOP/byte).

3. Этап 2. Расчёт Arithmetic Intensity для операторов (30 мин):

* расчёт FLOPs и Bytes для Fully-Connected, Conv2D, Attention;

* вычисление AI = FLOPs / Bytes для каждого оператора;

* оформление результатов в виде таблицы.

4. Этап 3. Построение Roofline-диаграммы (20 мин):

* построение графика в логарифмическом масштабе (ось X — AI, ось Y — производительность);

* нанесение горизонтальной линии Peak FLOP/s и наклонной линии P = AI × Peak Bandwidth;

* нанесение точек операторов и точки перегиба (ridge point).

5. Этап 4. Классификация и анализ (15 мин):

* определение типа ограничения (memory-bound/compute-bound) для каждого оператора;

* формулирование рекомендаций по оптимизации (увеличение batch, квантизация, fusion операций, использование тензорных ядер).

6. Этап 5. Анализ влияния batch size (10 мин):

* расчёт AI при batch = 1, 64, 256 для одного из операторов;

* определение минимального batch size перехода из memory-bound в compute-bound.

7. Заключительная часть (5 мин) — подведение итогов, обсуждение связи Roofline-анализа с выбором платформы (Лекция 3.1).

**Критерии оценки:** балльная система, максимум 10 баллов (см. документ «Критерии оценки практики. Модуль 3»).

**Требования к отчёту:**

* Структура: титульный лист; теоретическая справка (Roofline Model, Ridge Point); расчётная часть (таблицы FLOPs/Bytes/AI); Roofline-диаграмма; анализ и классификация операторов; выводы.

* Обязательные элементы: таблица классификации операторов (AI, AI_ridge, тип, рекомендации); график Roofline с нанесёнными точками; анализ влияния batch size.

* Срок сдачи: отчёт в формате PDF не позднее 7 календарных дней после занятия.

**Полезные формулы:**

```python
def ridge_point(peak_tflops, bandwidth_gbs):
    return peak_tflops * 1e12 / (bandwidth_gbs * 1e9)

ridge = ridge_point(312, 2000)  # 156.0 FLOP/byte
```

**Источники для углублённого изучения:** Williams, Waterman, Patterson. "Roofline: An Insightful Visual Performance Model" (2009); NVIDIA Nsight Compute Documentation.

**ПРАКТИЧЕСКОЕ ЗАНЯТИЕ (ПР6). Расчёт архитектуры LLM: VRAM, пропускная способность, квантизация и перплексия**

**Цели занятия:**

* Научиться выполнять инженерный расчёт требований к аппаратным ресурсам для инференса LLM (на примере LLaMA-3).

* Освоить методы квантизации (GPTQ, AWQ, BitsAndBytes, GGUF) для снижения требований к памяти.

* Научиться измерять и интерпретировать метрику perplexity для оценки потери качества.

**Формируемые компетенции:**

* HPC-1.1 – обеспечивает выбор наилучшей вычислительной архитектуры под задачу ИИ.

* HPC-1.2 – разрабатывает эффективные вычислительные реализации параллельных алгоритмов ИИ на современных архитектурах.

**Материалы и инструменты:**

* Python 3.8+ с библиотеками Transformers, BitsAndBytes, AutoGPTQ.

* llama.cpp для конвертации в GGUF и измерения perplexity.

* Доступ к моделям LLaMA-3 8B/70B на Hugging Face Hub.

* Датасеты WikiText-2 и C4 для измерения perplexity.

* CUDA-совместимая GPU (A100/RTX 4090) или CPU-режим для GGUF.

**Ход занятия:**

1. Вводная часть (10 мин) — постановка целей, обзор архитектуры LLaMA-3 (8B, 70B, GQA).

2. Этап 1. Расчёт VRAM для LLaMA-3 в разных форматах (25 мин):

* расчёт объёма весов модели в FP16, INT8, INT4 (Q4_K_M);

* расчёт объёма KV-кэша с учётом GQA (num_kv_heads);

* заполнение сводной таблицы VRAM для LLaMA-3 8B и 70B.

3. Этап 2. Оценка пропускной способности и задержки (20 мин):

* расчёт теоретической минимальной задержки на токен: Time per token = Weights(GB) / Bandwidth(GB/s);

* сравнение конфигураций на A100, RTX 4090, H100.

4. Этап 3. Применение квантизации (25 мин):

* выполнение квантизации LLaMA-3 8B одним из методов (BitsAndBytes NF4, AutoGPTQ, GGUF);

* фиксация размера модели до/после квантизации, времени загрузки и скорости инференса.

5. Этап 4. Измерение Perplexity (15 мин):

* измерение PPL исходной и квантизованной модели на WikiText-2 и C4;

* заполнение таблицы результатов с расчётом ΔPPL.

6. Заключительная часть (5 мин) — обсуждение выбора оптимальной конфигурации для разных сценариев (облако, Edge, игровой GPU).

**Критерии оценки:** балльная система, максимум 10 баллов (см. документ «Критерии оценки практики. Модуль 3»).

**Требования к отчёту:**

* Структура: титульный лист; теоретическая справка (архитектура LLaMA-3, расчёт VRAM, методы квантизации); расчётная часть (таблицы VRAM, задержки, PPL); графики зависимости perplexity от размера модели; анализ и рекомендации; выводы.

* Обязательные элементы: таблица VRAM по форматам; таблица задержек по GPU; таблица PPL с ΔPPL; рекомендации по выбору конфигурации для трёх сценариев использования.

* Срок сдачи: отчёт в формате PDF не позднее 7 календарных дней после занятия.

**Полезные команды:**

```bash
python convert.py /path/to/llama-3-8b --outfile llama-3-8b-fp16.gguf
./quantize llama-3-8b-fp16.gguf llama-3-8b-q4_k_m.gguf Q4_K_M
./perplexity -m llama-3-8b-q4_k_m.gguf -f wikitext-2-raw/test.txt
```

**Источники для углублённого изучения:** AWQ: Activation-aware Weight Quantization (arXiv:2306.00978); AutoGPTQ Documentation; llama.cpp Perplexity Evaluation Workflow.
