**ПРАКТИЧЕСКОЕ ЗАНЯТИЕ (ЛР7). Бенчмаркинг и нагрузочное тестирование систем инференса LLM на базе Triton Inference Server и vLLM**

**Цели занятия:**

* Освоить инструмент perf_analyzer для бенчмаркинга производительности моделей, развёрнутых на Triton Inference Server.

* Изучить методику нагрузочного тестирования vLLM-сервисов с использованием Locust.

* Научиться интерпретировать результаты бенчмаркинга и принимать решения о настройке конфигурации инференс-сервера.

* Сравнить подходы к оценке производительности для разных архитектур инференса.

**Формируемые компетенции:**

* LC-5.1 – осуществляет выбор инструментов и инженерных практик промышленной разработки, развёртывания и сопровождения моделей МО в продуктивной среде; тестирует и оценивает качество инструментов в рабочей версии ПО.

* HPC-1.2 – разрабатывает эффективные вычислительные реализации параллельных алгоритмов ИИ на современных архитектурах.

**Материалы и инструменты:**

* Docker и NVIDIA Container Toolkit; NVIDIA Triton Inference Server SDK container (nvcr.io/nvidia/tritonserver:*-py3-sdk); vLLM с OpenAI-совместимым API-сервером.

* Python 3.8+ с библиотеками locust, openai, numpy, matplotlib/seaborn.

* CUDA-совместимая GPU (рекомендуется) или CPU-режим для ознакомления.

* Модель для тестирования: Qwen/Qwen2.5-0.5B-Instruct (лёгкая модель для быстрого развёртывания).

**Ход занятия:**

1. Вводная часть (10 мин) — постановка целей, обзор экосистемы инструментов (Triton, perf_analyzer, vLLM, Locust).

2. Часть 1. Развёртывание и базовый бенчмаркинг с Triton perf_analyzer (30 мин):

* запуск Triton Inference Server через Docker;

* запуск perf_analyzer с параметрами --concurrency-range, --measurement-mode, -i (http/grpc), --shape;

* анализ Throughput, Latency (p50/p90/p95/p99), сравнение HTTP vs gRPC.

3. Часть 2. Развёртывание vLLM и нагрузочное тестирование с Locust (35 мин):

* запуск vLLM-сервера с OpenAI-совместимым API (`python -m vllm.entrypoints.openai.api_server`);

* написание Locust-скрипта (locustfile.py) для эмуляции пользователей, обращающихся к `/v1/chat/completions`;

* запуск нагрузочного теста (веб-режим или headless с отчётом `--html report.html`);

* сбор метрик: RPS, среднее время ответа и процентили, TTFT, уровень ошибок.

4. Часть 3. Сравнительный анализ и оптимизация (10 мин):

* сопоставление подходов perf_analyzer (низкоуровневый, точный) и Locust (высокоуровневый, эмуляция пользователей);

* эксперимент с оптимизацией: включение dynamic batching в config.pbtxt (Triton) или изменение --max-num-batched-tokens/--max-num-seqs (vLLM), повторный прогон и сравнение результатов.

5. Заключительная часть (5 мин) — подведение итогов, рекомендации по углублённому изучению (Triton Model Analyzer, интеграция vLLM как бэкенда Triton, распределённое тестирование Locust).

**Критерии оценки:** зачёт/незачёт (см. документ «Критерии оценки практики. Модуль 4»).

**Требования к отчёту:**

* Структура: титульный лист; цель работы; ход выполнения (Triton+perf_analyzer, vLLM+Locust, эксперимент с оптимизацией); результаты (таблицы/графики); анализ результатов; выводы; приложения (код Locust-скрипта, конфигурационные файлы).

* Обязательные элементы: таблица результатов perf_analyzer по уровням параллелизма; график throughput vs concurrency; таблица/график результатов Locust (RPS, задержки, ошибки); сравнительная таблица Triton vs vLLM; выводы о влиянии оптимизации.

* Срок сдачи: отчёт в формате PDF не позднее 7 календарных дней после занятия.

**Полезные команды:**

```bash
perf_analyzer --help
perf_analyzer -m simple --shape input:1,16
perf_analyzer -m simple -f results.csv
locust -f locustfile.py --host=http://localhost:8001 --web-port 8089
locust -f locustfile.py --host=http://localhost:8001 --csv=results
```

**Источники для углублённого изучения:** NVIDIA Triton Performance Guide (Performance Analyzer, Optimization); vLLM documentation (Benchmarking); Locust official documentation; Triton vLLM Backend Tutorial.

**ПРАКТИЧЕСКОЕ ЗАНЯТИЕ (ЛР8). Финальный проектный кейс: end-to-end обучение → оптимизация → инференс → мониторинг**

**Цель проектного задания:**
Разработать и развернуть веб-сервис инференса LLM на базе Triton Inference Server и/или vLLM для решения прикладной задачи, поставленной индустриальным партнёром — с полным циклом от выбора модели и архитектуры до настройки производительности под заданные аппаратные ограничения.

**Формируемые компетенции:**

* LC-5.1 – выбор инструментов и практик промышленной разработки, развёртывания и сопровождения моделей МО.

* HPC-1.1 – обеспечивает выбор наилучшей вычислительной архитектуры под задачу ИИ.

* HPC-1.2 – разрабатывает эффективные вычислительные реализации параллельных алгоритмов ИИ.

**Формат работы:** командный проект (распределение ролей внутри группы).

**Этапы выполнения проекта:**

1. **Формулировка задачи и выбор модели (1-я неделя):** постановка требований к сервису (предметная область, качество ответов, RPS/latency p50-p95-p99, бюджетные ограничения); выбор LLM с учётом размера, контекстного окна, совместимости с Triton/vLLM, доступности на Hugging Face; выбор целевой архитектуры (локальный сервер / облако) и обоснование.

2. **Проектирование решения и распределение ролей (1-я неделя):** распределение зон ответственности в команде; минимум 3 коммита в репозиторий на участника.

3. **Развёртывание и настройка (2-я неделя):** развёртывание Triton (model repository, config.pbtxt: dynamic_batching, instance_group, optimization) и/или vLLM (--max-num-batched-tokens, --max-num-seqs, --gpu-memory-utilization); настройка мониторинга (Prometheus/Grafana) и логирования.

4. **Бенчмаркинг и оптимизация (3-я неделя):** проведение бенчмаркинга (perf_analyzer, Locust); сбор throughput, latency p50/p90/p95/p99, TTFT; подбор оптимальных параметров; проверка размещения модели в VRAM (nvidia-smi), при необходимости — квантизация (INT8/FP8/AWQ).

5. **Оформление результатов (4-я неделя):** структурированный репозиторий (README, docker/, model_repository/, benchmarks/, monitoring/, src/, docs/report.md); итоговый отчёт.

**Структура репозитория:**

```
project/
├── README.md
├── docker/
│   ├── Dockerfile.triton
│   └── docker-compose.yml
├── model_repository/
│   └── <model_name>/
│       ├── config.pbtxt
│       └── <version>/
├── benchmarks/
│   ├── perf_analyzer/
│   └── locust/
├── monitoring/
│   ├── prometheus.yml
│   └── grafana/
├── src/
│   └── client.py
└── docs/
    └── report.md
```

**Структура отчёта:** титульный лист; постановка задачи; архитектурные решения; зоны ответственности; ход выполнения; результаты бенчмаркинга; оптимизация; выводы; приложения.

**Примерные темы проектов (по согласованию с индустриальным партнёром):**

* Чат-бот для техподдержки — модель 7B, контекст 4K, RPS ≥ 10, latency p95 < 500 мс.

* Генератор кода — модель 7B–13B, контекст 8K, RPS ≥ 5, latency p95 < 1 с.

* Анализатор документов — модель 7B, контекст 16K (или с RAG), RPS ≥ 3.

* Переводчик — модель 7B, контекст 2K, RPS ≥ 20.

* Суммаризатор новостей — модель 3B–7B, контекст 4K, RPS ≥ 15.

**Технические рекомендации по выбору модели:**

* Ограниченный GPU (8–16 ГБ VRAM): facebook/opt-350m, microsoft/phi-2, Qwen2.5-0.5B/1.5B.

* Средний GPU (24 ГБ VRAM): meta-llama/Llama-2-7b, Qwen2.5-7B.

* Мощный GPU (40+ ГБ VRAM): meta-llama/Llama-3-8B, Qwen2.5-14B/32B.

**Критерии защиты проекта:** защита в формате презентации (10–15 минут) с ответами на вопросы: почему выбрана модель и архитектура; какие параметры настраивались; основные проблемы и их решение; проверка размещения в VRAM; интерпретация полученных метрик.

**Критерии оценки:** см. документ «Критерии оценки практики. Модуль 4» (техническая реализация — 50 баллов, бенчмаркинг и тестирование — 25 баллов, оформление и командная работа — 25 баллов).
