# Проектная работа

Проектная работа — интегральный КИМ, позволяющий проверить несколько компетенций и индикаторов в условиях комплексной практической задачи.

---

## Пример кейса индустриального партнёра

Подробное описание примера кейса см. в файле [`case-example.md`](case-example.md).

### Краткое описание

Разрабатывается веб-сервис обработки запросов на естественном языке для BI-системы компании-партнёра. Система позволяет пользователям формулировать запросы на русском языке, которые с помощью LLM классифицируются и преобразуются в JSON-параметры для вызова веб-сервиса отчётов.

### Цель проекта

Создать веб-сервис для классификации и обработки запросов пользователей с преобразованием их в JSON для вызовов типовых отчётов с фактическими параметрами, извлекаемыми из запроса с помощью LLM.

### Ожидаемый результат

- Веб-сервис для обработки запросов на естественном языке.
- Библиотека промптов для LLM, позволяющая извлекать параметры запросов данных о продажах.

### Технические требования

- **RPS:** ≥ 2
- **Latency p95:** < 500 мс
- **Контекст:** 4K токенов
- **Модель:** на Hugging Face
- **GPU:** NVIDIA RTX 3060 (12 ГБ VRAM)
- **Срок:** 3 недели

### Описание API

API предоставляет список сделок с возможностью фильтрации и сортировки по следующим полям: `ID`, `TITLE`, `TYPE_ID`, `CATEGORY_ID`, `STAGE_ID`, `PRICE`, `MANAGER_ID`, `DATE_CREATE`.

Подробные форматы `FILTER` и `ORDER`, а также примеры запросов и ответов описаны в файле [`case-example.md`](case-example.md).

## Стандарты и артефакты ответственного жизненного цикла

Финальный проект должен включать следующие артефакты, основанные на международных стандартах ISO/IEC и рамках NIST. Данные артефакты интегрированы в существующие категории оценивания (техническая реализация — 50 баллов, бенчмаркинг — 25 баллов, оформление — 25 баллов) и не увеличивают общую сумму 100 баллов.

### 1. Паспорт модели и сервиса

Документ, содержащий:
- назначение модели и сервиса;
- модель и версия (название, версия, лицензия);
- аппаратная и программная конфигурация (GPU, VRAM, ОС, зависимости);
- ограничения (размер контекста, точность, latency);
- владелец и дата обновления.

### 2. Реестр рисков

Таблица рисков:
- риск;
- причина;
- вероятность;
- влияние;
- мера контроля;
- остаточный риск;
- ответственный.

### 3. Паспорт данных

Документ по данным:
- источник и лицензия;
- состав и формат;
- ограничения и потенциальные смещения;
- качество и методы проверки входных данных.

### 4. Матрица качества и SLO

Метрики качества и сервисные уровни:
- качество ответа ML/LLM (точность, perplexity, F1);
- P95 latency;
- throughput (RPS);
- error rate;
- потребление VRAM/RAM;
- доступность (availability);
- критерии деградации и rollback.

### 5. LLM/GenAI safety checklist

Проверка безопасности при использовании LLM/GenAI:
- hallucination (частота и влияние);
- prompt injection (устойчивость контекста);
- leakage of secrets/personal data;
- harmful или inappropriate output;
- out-of-scope requests;
- журналирование и аудит;
- human escalation и feedback.

Эти артефакты оцениваются в рамках существующих категорий: техническая реализация, бенчмаркинг и тестирование, оформление и командная работа. Подробные примеры заполнения см. в [`case-example.md`](case-example.md).
