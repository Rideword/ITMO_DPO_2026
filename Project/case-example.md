# Пример кейса компании индустриального партнёра

## «Веб-сервис обработки запросов на естественном языке для BI-системы»

### Описание

Для разрабатываемой компанией-партнёром BI-системы создаётся интерфейс на естественном языке для построения отчётов на больших массивах данных. С помощью LLM необходимо классифицировать запросы пользователей на естественном языке и извлекать фактические параметры для дальнейшего вызова веб-сервиса отчётов.

### Цель

Разработать веб-сервис для классификации и обработки запросов пользователей и преобразования их в JSON для вызовов типовых отчётов с фактическими параметрами, извлекаемыми из запроса с помощью LLM.

### Ожидаемый результат

Веб-сервис и библиотека промптов для LLM, позволяющие обрабатывать запросы на естественном языке и извлекать из них параметры для запроса данных о продажах.

---

### API запросов по продажам

API позволяет выдавать список сделок с фильтрацией и сортировкой по следующим параметрам:

| № | Поле | Описание |
| :---- | :---- | :---- |
| 1 | `ID` | Идентификатор |
| 2 | `TITLE` | Название (например, «Продажа 3-комнатной квартиры в ЖК Летний, Краснодар») |
| 3 | `TYPE_ID` | Тип сделки: 1 = дом, 2 = квартира, 3 = коммерческая недвижимость, 4 = комплексная сделка |
| 4 | `CATEGORY_ID` | Идентификатор воронки: 1 = отдел продаж для физлиц, 2 = отдел продаж для юрлиц |
| 5 | `STAGE_ID` | Стадия: 1 = новая сделка, 2 = договор отправлен, 3 = договор подписан, 4 = оплата получена, 5 = акты подписаны, 6 = замечания от заказчика, 7 = закрыта, 8 = отменена |
| 6 | `PRICE` | Сумма сделки в рублях |
| 7 | `MANAGER_ID` | Ответственный: 1 = Синица Сергей Геннадьевич, 2 = Добровольская Наталья Юрьевна, 3 = Подколзин Вадим Владиславович, 4 = Харченко Анна Владимировна, 5 = Коваленко Анна Владимировна, 6 = Колотий Александр Дмитриевич |
| 8 | `DATE_CREATE` | Дата создания в формате `YYYY-MM-DD` |

### Входные данные

На вход поступают запросы пользователей на русском языке, например:

1. «Выведи самые дорогие сделки Сергея Синицы в октябре 2025?»
2. «Какая была самая дорогая продажа за 2025 год?»
3. «Сколько сделок на стадии "Отменена" за 25 год у Анны Владимировны?»
4. «Сколько сделок с юрлицами было в 2024 году по сравнению с 2025?»

Запросы могут касаться любых полей и их комбинаций.

Необходимо из запроса на естественном языке сформировать две строки — `FILTER` и `ORDER` — в формате JSON с условиями фильтрации и сортировки сделок соответственно.

---

### Формат FILTER

`FILTER` — строка вида:

```json
{
  "field_1": "value_1",
  "field_2": "value_2",
  "...": "...",
  "field_n": "value_n"
}
```

Где:

- `field_n` — название поля, по которому будет отфильтрована выборка элементов;
- `value_n` — значение фильтра.

К ключам `field_n` можно добавить префикс, уточняющий работу фильтра. Возможные значения префикса:

| Префикс | Значение |
| :---- | :---- |
| `>=` | больше либо равно |
| `>` | больше |
| `<=` | меньше либо равно |
| `<` | меньше |
| `@` | IN, в качестве значения передаётся массив |
| `!@` | NOT IN, в качестве значения передаётся массив |
| `%` | LIKE, поиск по подстроке (без символа `%` в значении; ищет подстроку в любой позиции строки) |
| `=%` | LIKE, поиск по подстроке; символ `%` нужно передавать в значении |
| `%=` | LIKE (аналогично `=%`) |
| `=` | равно, точное совпадение (используется по умолчанию) |
| `!=` | не равно |
| `!` | не равно |

**Примеры использования `%` в значении для `=%`:**

- `"мол%"` — ищет значения, начинающиеся с «мол»
- `"%мол"` — ищет значения, заканчивающиеся на «мол»
- `"%мол%"` — ищет значения, где «мол» может быть в любой позиции

**Пример FILTER** для запроса «Выбери с 1-го октября новые сделки физлиц с названием, заканчивающимся на "а", от 10 до 20 тыс. руб., ответственный Сергей Геннадьевич или Александр Дмитриевич»:

```json
{
  "=%TITLE": "%а",
  "CATEGORY_ID": 1,
  "TYPE_ID": "4",
  "STAGE_ID": 1,
  ">PRICE": 10000,
  "<=PRICE": 20000,
  "@MANAGER_ID": [1, 6],
  ">DATE_CREATE": "2025-10-01"
}
```

---

### Формат ORDER

`ORDER` — строка вида:

```json
{
  "field_1": "value_1",
  "field_2": "value_2",
  "...": "...",
  "field_n": "value_n"
}
```

Где:

- `field_n` — название поля, по которому будет произведена сортировка выборки сделок;
- `value_n` — значение типа string, равное `ASC` (сортировка по возрастанию) или `DESC` (сортировка по убыванию).

**Пример ORDER** для поиска самых дорогих сделок:

```json
{
  "PRICE": "DESC",
  "TITLE": "ASC"
}
```
