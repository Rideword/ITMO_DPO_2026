Методические указания преподавателю по лекционному материалу (коротко). Модуль 1.

Общая цель модуля: сформировать у студентов инженерный подход к классификации и выбору вычислительных архитектур для задач ИИ на основе количественных моделей (Roofline, законы Амдала/Густафсона, TCO).

**Лекция 1.1. Классификация архитектур и основы выбора платформы**

Перед лекцией подготовить:
сравнительную таблицу CPU/GPU/TPU/FPGA/NPU по пиковой производительности, пропускной способности памяти, TDP и цене (см. конспект лекции, раздел 5);
пример расчёта арифметической интенсивности для 2–3 типовых операций.

Демонстрация должна включать:
разбор таксономии Флинна (SISD/SIMD/MISD/MIMD) на примерах реальных архитектур;
вывод и обсуждение формулы закона Амдала — акцент на том, что последовательная часть алгоритма ограничивает ускорение при росте числа ядер;
введение сквозного инженерного кейса «ВидеоАналитика+» (компания выбирает платформу для обучения CNN-модели обнаружения дефектов, ~50 млн параметров, датасет 10 млн изображений, срок обучения 7 дней) — кейс постепенно развивается на лекциях 1.1–1.4 и подводит студентов к практическим работам ПР1/ПР2.

**Лекция 1.2. Архитектура GPU и модели производительности**

Перед лекцией подготовить:
при наличии GPU в аудитории — демонстрацию вывода `nvidia-smi` (и, по возможности, `dcgmi`);
пример расчёта Occupancy и Roofline-точки для NVIDIA A100 (см. конспект, раздел 5).

Демонстрация должна включать:
разбор архитектуры SM/warp/Tensor Cores на схеме;
расчёт требуемого количества GPU для кейса «ВидеоАналитика+» с учётом перехода FP32 → FP16+Tensor Cores;
явную связь с предстоящей ПР1 (профилирование GPU): показать, какие именно метрики из лекции (occupancy, пропускная способность памяти) студенты будут самостоятельно снимать профилировщиком на практике.

**Лекция 1.3. Альтернативные платформы: FPGA и NPU в инженерной практике**

Перед лекцией подготовить:
сравнительную таблицу FPGA/NPU/GPU по TOPS/Вт, задержке и сложности разработки (см. конспект, раздел 5).

Демонстрация должна включать:
разбор кейса периферийного инференса (1000 потоков видео, задержка < 50 мс) со сравнением NVIDIA Jetson Orin, AMD Versal AI Edge и Google Coral NPU;
обсуждение экономики решения — расчёт TCO для парка из 1000 устройств.

**Лекция 1.4. Сравнительный анализ и выбор платформы (инженерный синтез)**

Перед лекцией подготовить:
итоговую таблицу решения по кейсу «ВидеоАналитика+» (см. конспект, раздел 5) для разбора на занятии;
шаблон сравнительной/взвешенной матрицы решений для демонстрации методологии выбора платформы.

Демонстрация должна включать:
пошаговый разбор методологии выбора платформы (сбор требований → анализ нагрузки → предварительный отбор → количественное сравнение → проверка экосистемы → решение);
итоговое обоснованное решение по кейсу «ВидеоАналитика+» с расчётом TCO;
явный переход к практическим работам: разъяснить, что ПР1 (профилирование GPU) и ПР2 (бенчмаркинг платформ) дадут студентам инструменты для количественного обоснования подобных инженерных решений на реальном оборудовании.

**Общие методические рекомендации**

Использовать файл «Вопросы к лекциям» (`Module-1_Lectures_Questions.md`) как основу для входного контроля перед практическими занятиями и как банк вопросов для устной защиты на дифференцированном зачёте.

Кейс «ВидеоАналитика+» — сквозной пример, разворачивающийся от лекции к лекции; рекомендуется кратко напоминать его условия и промежуточные результаты в начале каждой следующей лекции модуля.

Материалы модуля тесно связаны с практикой: без понимания Roofline-модели, occupancy и TCO (лекции 1.1–1.2, 1.4) студентам сложно осмысленно интерпретировать метрики, полученные в ПР1 (профилирование) и ПР2 (бенчмаркинг).
