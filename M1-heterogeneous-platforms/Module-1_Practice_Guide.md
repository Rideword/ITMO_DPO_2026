**Практические занятия по модулю 1**

**Дисциплина:** «Аппаратно-программные платформы для систем ИИ».
**Модуль 1. Гетерогенные вычислительные платформы для систем ИИ**

---

**ПРАКТИЧЕСКОЕ ЗАНЯТИЕ (ПР1). Профилирование GPU**

**Цели занятия:**

* Освоить инструменты профилирования GPU: nvidia-smi, NVIDIA DCGM, PyTorch Profiler.

* Научиться собирать и интерпретировать метрики загрузки SM, памяти, CPU/GPU-времени.

* Научиться выявлять ограничивающий фактор производительности (bottleneck) на реальном обучении/инференсе модели.

**Формируемые компетенции:**

* HPC-1.2 (базовый) — разрабатывает эффективные вычислительные реализации, запускает профилировщик, интерпретирует утилизацию SM и пропускную способность памяти.

**Материалы и инструменты:**

* ПК/сервер с Ubuntu 22.04 LTS и NVIDIA GPU (RTX 3060+, от 8 ГБ VRAM); драйверы NVIDIA + CUDA Toolkit 12.x.

* Python 3.11+, PyTorch 2.x; nvidia-smi; NVIDIA DCGM; torch.profiler (PyTorch Profiler) + TensorBoard для визуализации трасс.

* Тестовая модель: ResNet-50 (torchvision) или BERT-base (Hugging Face) — по указанию преподавателя.

**Ход занятия:**

1. Вводная часть (10 мин) — постановка целей, краткий обзор инструментов профилирования (nvidia-smi, DCGM, PyTorch Profiler).

2. Этап 1. Мониторинг GPU через nvidia-smi (30 мин):

* запуск `nvidia-smi dmon` / `nvidia-smi -l 1` в реальном времени во время обучения/инференса тестовой модели;

* фиксация утилизации GPU, памяти, температуры и энергопотребления (TDP).

3. Этап 2. Профилирование через NVIDIA DCGM (30 мин):

* настройка `dcgmi`, сбор расширенных метрик (SM Activity, Tensor Core Utilization, PCIe/NVLink throughput);

* сравнение показаний DCGM с показаниями nvidia-smi.

4. Этап 3. Профилирование PyTorch-модели через torch.profiler (60 мин):

* оборачивание цикла обучения/инференса профилировщиком (`torch.profiler.profile`);

* сбор трасс CPU/GPU, экспорт в Chrome Trace / просмотр в TensorBoard;

* анализ времени выполнения по операторам (топ самых затратных операций).

5. Этап 4. Выявление узких мест (40 мин):

* сопоставление данных nvidia-smi/DCGM и torch.profiler;

* определение ограничивающего фактора (compute GPU, пропускная способность памяти, загрузка данных на CPU, передача по PCIe);

* формулирование минимум одной гипотезы по оптимизации (batch size, num_workers, mixed precision и т. п.).

6. Заключительная часть (10 мин) — фиксация наблюдений, подготовка структуры отчёта.

**Критерии оценки:** балльная система, максимум 100 баллов (см. документ «Критерии оценки практики. Модуль 1»).

**Требования к отчёту:**

* Структура: титульный лист; описание тестовой модели и окружения; результаты nvidia-smi; результаты DCGM; результаты torch.profiler (трассы/скриншоты); анализ узкого места; рекомендации по оптимизации; заключение; список источников.

* Объём: 8–12 страниц, шрифт Times New Roman 14, полуторный интервал.

**Источники для углублённого изучения:** NVIDIA CUDA Programming Guide; PyTorch Profiler documentation; NVIDIA DCGM Documentation; NVIDIA Deep Learning Institute (DLI).

**ПРАКТИЧЕСКОЕ ЗАНЯТИЕ (ПР2). Бенчмаркинг платформ**

**Цели занятия:**

* Провести воспроизводимый бенчмарк ResNet-50 или BERT-base на доступной GPU-платформе.

* Измерить latency, throughput, потребление памяти и утилизацию GPU при разных конфигурациях.

* Сопоставить измеренные показатели с теоретическими характеристиками платформы (Peak FLOPS, пропускная способность памяти).

**Формируемые компетенции:**

* HPC-1.1, HPC-1.2 (базовый) — измеряет latency/throughput/TDP, сопоставляет с теоретическими характеристиками платформы.

**Материалы и инструменты:**

* Та же среда, что и в ПР1 (GPU, Python 3.11+, PyTorch 2.x).

* `torch.utils.benchmark` или собственный скрипт замера latency/throughput; nvidia-smi для контроля памяти/утилизации во время замеров.

* Открытые бенчмарки MLPerf/MLCommons для сопоставления с эталонными показателями.

**Ход занятия:**

1. Вводная часть (10 мин) — постановка целей, краткий обзор методики бенчмаркинга MLPerf (warm-up, число итераций, фиксация конфигурации).

2. Этап 1. Подготовка бенчмарка (20 мин):

* выбор модели (ResNet-50 или BERT-base), подготовка тестовых/синтетических входных данных;

* настройка warm-up-итераций и числа измерительных прогонов.

3. Этап 2. Замер базовой производительности (30 мин):

* измерение latency (мс/запрос) и throughput (samples/sec или tokens/sec) при batch = 1, precision FP32.

4. Этап 3. Варьирование batch size и precision (60 мин):

* повтор замеров для batch = 1 / 8 / 32 / 128;

* повтор замеров для FP32 и FP16 (Tensor Cores);

* фиксация потребления памяти (nvidia-smi) и утилизации GPU для каждой конфигурации.

5. Этап 4. Анализ и сопоставление с теорией (40 мин):

* построение таблиц/графиков latency и throughput в зависимости от batch size и precision;

* сопоставление с теоретическими характеристиками платформы (Peak FLOPS, Bandwidth) — по аналогии с Roofline-подходом из лекций 1.1–1.2;

* определение точки насыщения (saturation) по batch size.

6. Заключительная часть (10 мин) — формулирование выводов об оптимальной конфигурации; обсуждение типичных ошибок измерений (отсутствие warm-up, thermal throttling).

**Критерии оценки:** балльная система, максимум 100 баллов (см. документ «Критерии оценки практики. Модуль 1»).

**Требования к отчёту:**

* Структура: титульный лист; методика бенчмаркинга; результаты (таблицы/графики latency/throughput по batch size и precision); сопоставление с теоретическими характеристиками платформы; выводы; список источников.

* Объём: 8–12 страниц, шрифт Times New Roman 14, полуторный интервал.

**Источники для углублённого изучения:** MLPerf Benchmarks (https://mlcommons.org/benchmarks/); PyTorch Profiler / torch.utils.benchmark documentation; NVIDIA Data Center GPU Documentation.
